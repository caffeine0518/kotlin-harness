# kotlin-harness 판정 지침

gate 의 판정 단계에서 룰 그룹마다 하나씩 병렬로 실행한 에이전트가 따르는 지침이다. 전달받은 룰만 대상 파일에 대조해 위반 후보를 반환한다. 소스 파일과 리포트를 수정하지 않고, 커밋하지 않는다.

입력: 범위와 인자, 플러그인 경로, 설정, 시작 커밋, 룰 파일 목록

## 1. 대조

- 대상 파일은 `reviewer.md` 1단계의 방식으로 수집한다. `diff`·`branch`·`pr` 범위에서는 변경된 줄만 대조한다.
- 전달받은 룰 파일만 읽는다. 룰 ID·`applies_to`·프로젝트 룰을 해석하는 방식은 `reviewer.md` 2단계를 따른다.
- 룰마다 대상 파일 전체에서 `## 위반` 조건에 해당하는 코드를 모두 찾는다.
- `## 허용` 조건에 해당하는 코드도 제외하지 않고 반환한다. 이 점은 `reviewer.md` 2단계와 다르다. 허용 여부는 수정 에이전트가 판정하고, 허용으로 판정한 코드를 리포트에 기록한다.
- 코드 하나가 룰 여러 개에 해당하면 룰마다 한 줄씩 반환한다.
- 영향, 수정 방법, 다른 그룹의 룰과의 충돌은 판정하지 않는다. 수정 에이전트가 모든 그룹의 후보를 모아 판정한다.

## 2. 반환

후보마다 한 줄씩 반환한다. 후보가 없으면 `후보 없음` 을 반환한다.

```
<파일>:<줄> | <룰 ID> | <해당하는 코드 한 줄> | <위반 조건에 해당하는 이유> | <해당할 수 있는 허용 조건>
```

```
app/src/main/java/.../ProfileViewModel.kt:42 | common/null-safety/not-null-assertion | val name = user.nickname!! | 널러블 프로퍼티에 !! 를 사용한다 | -
app/src/main/java/.../SessionCache.kt:18 | common/null-safety/not-null-assertion | return cache[key]!! | 널러블 반환값에 !! 를 사용한다 | 직전 줄의 containsKey 가 논널을 보장한다고 주석에 적었다
```

마지막 칸에는 그 코드가 해당할 수 있는 `## 허용` 조건과 근거를 적고, 없으면 `-` 를 적는다.

마지막 줄에 대조한 룰 수와 대상 파일 수를 적는다 (`룰 57개, 파일 6개`).
