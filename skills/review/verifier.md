# kotlin-harness 검수 지침

리뷰 에이전트가 작성한 리포트가 실제 코드·커밋과 일치하는지, 빠진 위반이 없는지 확인한다. 리뷰 에이전트의 판단을 신뢰하지 않고, 리포트·코드·git 이력만 근거로 처음부터 확인한다. 소스 파일을 수정하거나 커밋하지 않는다.

입력: 리포트 경로, 범위와 인자, 플러그인 경로, 설정, 시작 커밋, 작업 중인 파일, 검수 회차

## 검수 항목

### 1. 누락

대상 파일을 다시 수집하고(`reviewer.md` 1단계), 모든 룰(2단계)을 현재 코드에 대조한다. 리뷰 에이전트와 별개로 룰 파일을 하나씩 읽고 대상 파일 전체에 적용한다. 변경 줄이 대상인 범위는 시작 커밋 기준 변경 줄로 판정한다.

- 현재 코드에 남은 위반이 리포트에 없으면 `누락` 이다. 코드 하나가 룰 여러 개에 해당하면 룰마다 항목이 있어야 한다. 다른 룰 항목과 수정 방법이 같다는 이유로 빠진 것도 `누락` 이다.
- 수정으로 사라진 위반도 `git diff <시작 커밋>` 의 삭제된 줄을 룰에 대조해, 리포트에 항목이 있는지 확인한다.
- 리포트에 `수정함` 으로 적힌 위반이 코드에 남아 있으면 `수정 미완` 이다.
- 리포트에 `수정하지 않음` 이나 `autoFix 비활성화` 로 적힌 위반이 남아 있는 것은 정상이다.

### 2. 항목별 처리 결과

리포트의 위반마다 처리 결과가 사실인지 확인한다.

- `수정함 (커밋 <해시>)`: 커밋이 존재하고, 그 커밋이 해당 파일의 해당 코드를 수정했고, 수정 결과가 룰의 `## 수정` 과 맞는지
- `수정함 (커밋하지 않음: ...)`: 파일이 실제로 작업 중인 파일이거나 git 리포가 아닌지, 수정이 작업 트리에 반영됐는지
- `수정하지 않음: ...`: 이유가 `reviewer.md` 3단계의 수정하지 않는 경우에 실제로 해당하는지. 수정 방법이 하나로 정해지는데 수정하지 않았으면 `수정 누락` 이다.
- 처리 결과가 없는 항목

### 3. 변경 범위

`git log <시작 커밋>..HEAD`, `git diff <시작 커밋>..HEAD`, `git status` 로 확인한다.

- 리포트에 없는 변경, 위반과 관계없는 코드 변경이 없는지
- 작업 중인 파일이 커밋에 포함되지 않았는지
- 리포트 파일이 커밋되지 않았는지, 푸시되지 않았는지
- `autoFix` 가 `false` 이면 소스 변경과 커밋이 하나도 없는지

### 4. 커밋 메시지

`reviewer.md` 의 커밋 메시지 기준으로 확인한다. 룰 ID·카테고리 이름·`룰 위반`·줄 번호 나열·도구 이름이 있거나, 룰을 모르는 사람이 무엇을 왜 수정했는지 알 수 없으면 문제다.

### 5. 리포트 형식

- 요약의 건수, 룰별 집계, 위반 목록의 건수가 서로 일치하는지
- 모든 위반에 위치·규칙·근거·코드·위반 내용·처리가 있는지

## 결과 기록

리포트 끝에 아래 섹션을 추가한다. 이전 회차의 섹션이 있으면 그 아래에 이어서 적는다.

```markdown
## 검수 결과 (1회차)

| 항목 | 결과 |
|---|---|
| 누락 | 문제 1건 |
| 항목별 처리 결과 | 통과 |
| 변경 범위 | 통과 |
| 커밋 메시지 | 문제 1건 |
| 리포트 형식 | 통과 |

1. [누락] `app/.../Foo.kt:30` common/null-safety/safe-cast — `bundle.get("id") as String` 이 리포트에 없다
2. [커밋 메시지] `a1b2c3d` — 제목에 룰 ID 가 포함됐다
```

문제가 없으면 표만 적고 `문제 없음` 을 적는다.

## 반환

문제 목록만 반환한다. 문제가 없으면 `문제 없음` 을 반환한다.
