# 수정 이력·작성자·결함 배경을 주석으로 작성하지 않는다

## 이유

Robert C. Martin 의 《Clean Code》 4장은 수정할 때마다 기록을 추가하는 이력(journal) 주석과 작성자(attribution·byline) 주석을 쓰지 말라고 한다. 누가 언제 무엇을 바꿨는지는 버전 관리 시스템이 기록한다. 무엇이 왜 잘못되었는지도 커밋 메시지와 이슈에 적는다. 결함 배경을 코드에 적으면 두 곳에 기록되고, 수정된 뒤에도 남아 현재 동작을 설명하는 것처럼 읽힌다.

## 위반

- 날짜·작성자·수정 내역을 적은 주석 (`// 2024-03-02 dev: 캐시 추가`, `@author`)
- 이전 동작이나 결함을 설명하는 주석 (`// 예전에는 서버 응답으로 판정했는데 버그가 있어서 바꿨다`)
- 이슈 번호와 함께 무엇을 수정했는지만 적은 주석 (`// #1234 수정`)

```kotlin
/**
 * @author dev
 * 2024-03-02 캐시 추가
 * 2024-05-10 재시도 로직 수정
 */
class OrderRepository

// 예전에는 isVisible 을 서버 응답 유무로 판정해서 카드가 사라지는 버그가 있었다
val isVisible = cards.isNotEmpty()
```

## 수정

주석을 삭제하고, 필요한 내용은 커밋 메시지와 이슈에 적는다.

```kotlin
class OrderRepository

val isVisible = cards.isNotEmpty()
```

## 허용

- 현재 코드가 왜 이렇게 되어 있는지 설명하고, 그 근거가 되는 이슈 링크를 붙인 경우. 코드를 바꾸면 결함이 다시 발생한다는 경고가 여기에 해당한다 (`// 서버 응답이 없어도 카드가 있으면 표시해야 한다. 서버 응답으로 판정하면 #1234 가 다시 발생한다`).
- 외부 라이브러리 버그를 우회하는 코드와 관련 이슈 링크
- 라이선스·저작권 헤더
